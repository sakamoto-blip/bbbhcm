# 研修スライド（HTMLデッキ）のフォーマットとルール

2026年10月30日時点。第1〜6章（3-2章・5-2章を含む）のHTMLデッキに共通するルールです。章ごとの内容は、正規チャットのMD（マスターデータ・台本・投影用資料）が正です。

---

## 1. 前提

| 項目 | 内容 |
|---|---|
| 使い方 | Zoomで画面共有して投影する（約60分＋質疑） |
| 画面の大きさ | 1920×1080 の固定キャンバス。ブラウザの大きさに合わせて拡大・縮小する |
| ファイル | 編集用：`training/ch○○_○○.html`＋共通の `assets/deck.css`・`assets/deck.js`／配布用：1ファイルにまとめた `第○章_○○.html`（全章をzipにまとめて配布） |
| 確認用リンク | 章ごとにアーティファクト（claude.ai）で公開。修正のたびに同じリンクを更新する |

## 2. 見た目（テイスト）

- **地は、すべて淡い色**（濃い背景・黒背景は使わない）
- **フォント**：本文は普通のゴシック（Zen Kaku Gothic New）。数字だけ太い書体（Dela Gothic One）
- **色**：章ごとにアクセント色を1つ決め、それ以外は共通の色を使う

| 章 | アクセント色 |
|---|---|
| 第1章 防災管理 | 炎（オレンジ） |
| 第2章 衛生管理 | 緑 |
| 第3章 労務管理／第3-2章 ハラスメントからアジャストメントへ | 紫 |
| 第4章 経理管理 | 金 |
| 第5章 法務実務／第5-2章 メニューコンプライアンス | 青 |
| 第6章 情報管理 | ローズ |

  共通の色：赤＝危険・禁止・罰則、緑＝OK・やること・守られた状態、青＝補足・情報
- **人物**：人の形のピクトグラム（`#i-person`）を使う。3-2章では、**上の立場の人＝アクセント色、下の立場の人＝青**で描き分ける
- **表現**：極端な表現（恐怖をあおる絵・過激な言葉）は使わない
- **フッター**：中央に BALNIBARBI のロゴ。左に章名、右にクリックの進み具合とページ番号

## 3. 画面の作り方（文字と絵）

基準は、第3-2章の仕上がり。

> **必要な情報は、文章でも出す。台本をなぞるだけになる部分は、アニメーション・イラスト・図で補足する。**

- **1画面で伝えることは1つ**。見出しは15字前後
- **画面の文字は、130〜380字が目安**（図の中の文字を含む）。事例・表を見せるスライドは〜400字。800字を超えるものは必ず減らす
- **残す文**：定義・条件・数字・禁止事項・判断基準は、1〜2行の要点の文として画面にも出す（キーワードだけにしない）
- **台本へ移す文**：台本をそのまま読むような長文・説明文は、画面から外し、台本（notes）に残す。**台本の文章は減らさない**
- **箇条書き・手順・役割**は、絵・アイコン・図にする（フロー図、役割のアイコン、STOP標識、カード、対比、時間軸）
- **数字**は、図でも見せる（グラフ、メーター、人数のアイコン、大きな数字）。条件つきの数字（「5年以下の拘禁刑または100万円以下の罰金」など）は、文字でも残す
- **アイコン・図は、1枚に10個前後**が目安
- **やってはいけないことは赤（禁止・×・STOP）、やることは緑（決める・確認・✓）**で分け、見ただけでわかるようにする

## 4. 動き（アニメーション）

- **クリックで1つずつ出す**のが基本。台本の［クリック］と、画面の動きを1対1で対応させる
- 動きは**意味のあるものだけ**（順序・因果・対比・変化・強調）。装飾だけの動きは入れない
- 画面全体に、**ゆっくり動き続ける要素**を入れる（揺れる吹き出し、流れる矢印、点滅する警告など）
- 動きを減らす設定（prefers-reduced-motion）のブラウザでは、動きを止める

| やりたいこと | 方法 |
|---|---|
| クリックn回目で出す | `data-step="n"` |
| 最初からふわっと出す | `data-in`＋`style="--d:n"`（遅らせる） |
| 場面を切り替える | `div.phase`＋`data-until="n"`（n回目より後で消える） |
| 数字を数え上げる | `data-count="38"` |
| 時間を数え下げる | `data-countdown="30"`＋`data-fmt="mmss"` |
| 天秤（処分より命が重い） | `section` に `data-pun`・`data-life` |
| 予定時間 | `section` に `data-min="3"`（分） |

## 5. 台本（notes）

- 各スライドの `<aside class="notes">` に、**MDの台本をそのまま**入れる
- **［クリック］の数 ＝ そのスライドの `data-step` の最大値**（必ずそろえる）
- ［クリック］の前までが、そのクリックの前に話す内容
- 進行役への指示は「（進行役：…）」の形
- 画面から外した文章も、台本には残す

## 6. 操作（発表者向け）

| 操作 | キー |
|---|---|
| 次へ／戻る | → ・ スペース・クリック ／ ← |
| 全画面 | F |
| 発表者ウィンドウ（台本・経過時間・次のスライド） | P |
| 台本を画面下に表示 | N |
| スライド一覧 | 画面の下にマウスを近づける（クリックでそのページへ） |

## 7. スライドの型

### 7-1. 章の流れ（共通）

タイトル → まず、お答えください（冒頭の投票） → 事例 → なぜ起きるのか → 何を失うか → プラン・キープ・アクト（それぞれの前後にクイズ） → それでも起きたら（初動対応・事後対応） → 研修修了レポート → 最後に → 質疑応答
（3-2章は、プラン・キープ・アクトの代わりに「フィルター」と「アジャスター」の2本柱。ワーク3回を含む）

### 7-2. 各スライドのルール

| スライド | ルール |
|---|---|
| **タイトル** | 「第○章」と章名、サブタイトル。**「オンライン研修」「60分」は入れない** |
| **まず、お答えください** | **質問と回答のしかたを1枚にまとめる**。回答は**Zoomの投票**。台本の読み上げ例の「◯％」「◯件」は残し、その場で口頭で言う |
| **事例** | 実際の画面や出来事を再現する（LINE画面など）。数字はグラフで出す |
| **何を失うか** | **「会社」と「あなた個人」**に分ける。個人は**刑事・民事のラベル**をつける。罰則は**「拘禁刑」**（懲役・禁錮は使わない）。最後は「命」で締める（天秤の演出） |
| **クイズ** | 「クイズ ①」＋「Zoomの投票で回答」。**1回目のクリックでカウントダウン開始**（選択式30秒・記述式1分）→ **0:00で「時間です」を赤で表示** → **2回目のクリックで正解を表示**。1問2分（`data-min="2"`）。**「正解率◯％」などの入力欄は作らない** |
| **ワーク（3-2章）** | クリックでタイマー開始（2分・3分）。発表も回収もしない |
| **初動対応** | **ステップの矢印**（聞く・記録 → すぐ本部へ → …）＋**STOP標識**（独断で処理しない・報復しない・直接確認しない など）＋要点の文 |
| **事後対応** | **ステップのフロー**＋**「誰が」を示す役割のアイコン**（店長・シェフ → 担当役員 → 代表 → 総務人事部 など）＋要点の文 |
| **研修修了レポート** | 提出方法・期限（研修実施日から3日以内）・記入方法・QRコード。**レポートの項目は画面に並べない**（台本で話す） |
| **最後に** | キーメッセージと、相談先 |
| **質疑応答** | 1枚。ロゴのみのフッター |

## 8. 用語・表記

| 使わない | 使う |
|---|---|
| 懲役・禁錮 | **拘禁刑** |
| ハラスメント防止（3-2章の章名） | **ハラスメントからアジャストメントへ** |
| 拒絶コスト | **拒絶リスク** |
| メニューエビデンス提出／チェックシート | **メニューコンプライアンスチェック**／**該当項目チェック表** |
| アジャスターの順（シグナル→ノイズ→タイミング→アンガー） | **①アンガーマネジメント→②シグナル→③ノイズ→④タイミング** |

確定している連絡先：ハラスメント相談窓口 **soudan@garb.co.jp**（社員・アルバイトが使う窓口）／保険の社内窓口 **insurance@garb.co.jp**（担当者名は出さない）

## 9. 修正のルール

- **内容の正は、MD**。デッキがMDと食い違う場合は、MDに合わせる
- **改修指示書に載っているスライドだけを直す**。載っていないスライドを直した場合（担当者の判断・実装時の微調整）は、**直した箇所を正規チャットに報告する**
- 指示書で変更と書かれていない限り、**クリック数・台本の［クリック］・時間（`data-min`）は変えない**
- **テイスト（既存の見た目と部品）は変えない**。全面的な作り直しはしない
- **投票結果の入力欄（「◯％」をクリックして書き込む欄）は、全章で作らない・残さない**

## 10. 修正後の確認

1. スライドごとに、画面の文字数を数える（notesを除く）。目安を超えたら理由を残す
2. 全スライドで、［クリック］の数 ＝ `data-step` の最大値
3. 直したスライドを、クリックを進めながら画像で確認する（はみ出し・重なり・文字の小ささ）
4. 台本がMDと一致している（文章は減らさない）
5. 変更前のファイルと比べて、直したスライド以外が変わっていない
6. 確認用リンク・配布用HTML・全章zipを更新する
